# 质检修复报告 v3.0.550

## 一、防撤回系统提示修复（用户反馈「别人撤回没有提示」）

### 根因
v3.0.549 在插入提示行前增加了 setter 存在性检查（`e9.getDeclaredMethods()` 找 u1/b1/setType/k1/e1），
但微信 e9 的部分 setter 声明在**父类**，`getDeclaredMethods` 只返回当前类声明的方法，导致误判「缺少关键 setter」，
日志出现 `hint: e9 缺少关键 setter，放弃插入提示行`，用户因此看不到任何撤回提示。

### 修复内容
1. **移除 getDeclaredMethods 检查**：改为直接调用微信实证 setter 序列（u1/b1/setType/k1/e1/r1/r3），
   `XposedHelpers.callMethod` 会遍历父类查找方法，不再误判。
2. **新增构造后 read-back 验证**：入库前调用 `getType()` 验证消息 type==10000，
   若跨版本 setType 不存在导致 type 不正确，则放弃入库，避免产生 type=0 的脏消息。
3. **新增自定义撤回提示文字**：配置项「撤回提示自定义文字」，支持 `{name}` 占位符（自动替换为发送者昵称），
   留空使用默认文案「{name}撤回了一条消息（已防撤回保留）」。
   配置入口：联系人和群聊 → 消息防撤回 → 保留撤回失败提示 下方输入框。
4. **sHint 静态默认值修正**：与 prefs 默认值（true）保持一致。

## 二、群管理页面优化

1. **背景不透明**：弹窗不再使用 clearDialogShell（会清空窗口背景导致透明），
   改为窗口背景固定为 AppColors.surface() 实底色，滚动区背景同步不透明。
2. **上下间距压缩**：品牌头/分组标题/卡片/输入框/开关行的上下 padding 与 margin 由 10-16dp 统一压缩至 4-10dp。
3. **窗口自适配**：宽度 90% 屏、高度随内容自适应、上限 90% 屏，内容超长由 ScrollView 内部滚动；
   show 后再次固定窗口尺寸与背景，防止 AlertDialog.show 重置。
4. **群成员选择器重做**：新增 GroupMemberPickerDialog —— 与模块联系人选择器同款样式，
   支持头像 + 昵称/备注 + 搜索（昵称/wxid）+ 多选 + 全选，数据源为群成员 wxid 列表，
   昵称优先取内存联系人，未命中再查微信 rcontact 数据库。

## 三、审查结论
- 防撤回提示：默认文案/自定义模板/占位符替换逻辑正确，无空指针风险；
  提示行 type=10000 与微信系统提示一致（居中灰字），不再误插入普通气泡。
- 群管理：窗口不透明、尺寸自适配、成员选择器样式与模块一致。
- 编译：通过（assembleRelease）。

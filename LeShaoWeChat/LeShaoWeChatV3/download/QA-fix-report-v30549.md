# 质检修复报告 v3.0.549

本次在 v3.0.548 基础上完成防撤回与群管理改动的二次严格审查，并修复审查发现的问题。

## 一、防撤回审查修复

1. **H1 参数校验误判（高危）**
   - 原校验要求 `args[0] instanceof String`，但 `doRevokeMsg` 首参可能是 xmlSrvMsgId(long)/revokeFlag(int)，导致防撤回主路径可能整体失效。
   - 已修复：只要求 `args[3]`（replacemsg）是 String 即可，talker 统一用 `String.valueOf()` 兼容。

2. **「自己撤回」误判（中危）**
   - 原判断 `startsWith("你")`，对方昵称以「你」开头（如「你妹」「你是我的」）时会被误判为「自己撤回」而放行。
   - 已修复：收紧为 `startsWith("你撤回")`，精确匹配微信标准文案。

3. **提示行触发关键词回复（中高）**
   - 防撤回插入的 type=10000 系统提示行（「xxx撤回消息失败」）会被关键词回复当成真实消息处理。
   - 已修复：`processKeywordAndSensitive` 入口过滤 type=10000，系统提示不参与关键词回复/敏感词过滤。

4. **提示行关键 setter 静默失败（中危）**
   - `setType/k1/u1/b1/e1` 任一缺失时，提示行可能以 type=0 的残缺状态入库。
   - 已修复：构造提示行前先反射检查关键 setter 是否存在，任一缺失则放弃插入。

5. **「自己撤回也失效」开关无效（低危）**
   - 该功能已停用（存在缺陷），但开关仍可拨动。
   - 已修复：开关直接禁用（只展示不可操作）。

## 二、群管理重设计审查修复

1. **名单初始 Set 解析错误（P0）**
   - 原用 `listStr(...).split(",")` 解析 JSON 数组串，得到带引号/方括号的碎片，空名单产生幽灵项「无」。
   - 已修复：新增 `listSet()` 按 JSON 解析，返回干净 wxid 集合。

2. **全局名单不生效（P1）**
   - 全局设置（无群聊上下文）时名单写入 `""` 键，运行时查不到。
   - 已修复：`inList()` 合并检查全局段（`""` 键），全局名单生效。

3. **DexKit 动态定位缓存未验证类（P1）**
   - 原只验证类可加载，不验证方法存在性，可能命中无关类导致静默失效。
   - 已修复：缓存前先验证候选类确有「静态 1 参返回 List」方法。

4. **findStaticMethod 匹配过窄 + 未 setAccessible（P2）**
   - 原只匹配返回类型精确 `== List.class`，真实方法返回 ArrayList 时匹配不到；非 public 方法 invoke 失败。
   - 已修复：返回类型用 `isAssignableFrom`，校验参数类型可接收 String，并 `setAccessible(true)`。

5. **membersOf 不回退硬编码（P2）**
   - 动态方法缺失时直接返回空列表。
   - 已修复：三级回退（动态类 → 硬编码类动态方法 → 旧方法名 l41.u1.o）。

6. **成员列表高度塌陷（P2）**
   - wrap_content 对话框中 weight=1 的 ListView 可能被测量为 0 高度。
   - 已修复：ListView 固定高度 360dp。

7. **勾选状态不可区分（P2）**
   - `checkbox_on_background` 是静态选中图，未选中行也显示勾选框。
   - 已修复：改用 StateListDrawable（选中/未选中可切换）。

8. **成员选择行样式不统一（P3）**
   - 已补卡片背景与底部间距，与开关行一致。
   - 同时清理无用 import 与未使用变量。

## 三、审查结论

- 防撤回：H4 自己撤回在 sSelf 恒 false 下不会安装，无残留路径；别人撤回拦截 + 自己撤回放行逻辑成立。
- 群管理：名单格式兼容、保存逻辑正确、动态化有三级回退。
- 编译：通过（assembleRelease）。

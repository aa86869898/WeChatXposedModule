## 一、你这条链路的实际情况

链路是：分身发给大号 → 大号回复 → 回复回到分身 → 希望转发给大号。

日志的结论是：**在第一步之前就没走到**。

```
12:52:42.586 ModuleConfig: initWxid: wxid_9ohhf82mrlgc22         ← 分身自己
12:52:42.653 AutoForward: config: sources=1 targets=1 types=[1]
12:52:42.653 AutoForward: boot snapshot: head=wxid_qf3ok46p08v922 ← 来源=大号
```

整份日志里，`talker=wxid_qf3ok46p08v922` 的消息是 **0 条**。

`MessageHook` 共记录 49 条消息，全部是群聊；私聊只有 2 条，属于一个红包会话（`wxid_pvc12kgikl7s12`），不是大号。

也就是说：**你回复的那条消息没有以「收到」的形式进到 hook**。没有输入，后面的来源匹配、类型匹配、发送都无从谈起。

## 二、更正：分身与大号是两个不同的号

日志可证：

```
12:52:42.586 ModuleConfig: initWxid: wxid_9ohhf82mrlgc22    ← 分身自己
12:52:42.653 boot snapshot: head=wxid_qf3ok46p08v922         ← 大号（来源）
```

本报告上一版写「同一个号」是错的，已更正。

真正的原因是**这份日志没有覆盖测试动作**：窗口 `12:52:41 → 12:55:37`，模块 v3.0.586，`MessageHook` 共 49 条消息全部来自群聊，私聊 0 条，且没有 `config save`。测试消息既没发出去也没收回来，`fwd trigger=0` 是必然结果。

另外仍成立的一点：本实例自己发出的消息 `isSend=1` 会被跳过，来源侧必须由对方号发来。

## 三、本轮新增两件工具

### 1. 最近到达消息（面板）

列出最近 20 条**私聊 + 已选来源**消息：

```
12:55:03 私 wxid_qf3ok46p08v922 type=1 isSend=0 → 已转发 -> 1 个目标
12:55:01 私 wxid_qf3ok46p08v922 type=1 isSend=1 → 自己发送
```

- 列表为空：消息根本没进 hook，不用再查转发逻辑；
- 显示「自己发送」：到达的是自发副本，属正常拦截；
- 显示「来源不匹配」：到达会话不是勾选那个；
- 显示「已转发」：转发已执行，问题在目标侧。

### 2. 试发一条到目标（面板）

直接向前 3 个目标（首个、末个、第二个）发测试文本，绕开来消息：

- 成功：发送链路与目标正常，问题一定在来源侧；
- 失败：日志有 `test send -> <目标> err: ...`，错误可见。

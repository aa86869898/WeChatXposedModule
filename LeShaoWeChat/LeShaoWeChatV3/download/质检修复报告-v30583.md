## 一、问题

580-582 用「isSend 必须为 0」作接收门禁，本机发出的消息 isSend=1，安全。但**分身/多设备同步回来的同一条消息 isSend 也是 0**，正文又可能没有水印（用户手打、历史同步、语音无正文）：

```
主微信发出消息
        ↓
分身 B 收到同步副本：isSend=0 + fromUsername=自己
        ↓
B 当作「别人发来的新消息」→ 再点一次歌 / 再回一次 AI / 再转发一次
```

点歌语音没有正文，账本又是进程内的，B 分身完全拦不住。

## 二、修复

新增 `SelfMsgGuard.isSelfSender(e9)`：读消息发送者 `s0`（回退 `field_fromUsername`），与 `StorageHub.selfWxid()` 比较，相等即归属自己。判定只看身份，不依赖正文，语音同样生效。

接入三处接收链，均在 `isSend == 0` 分支内、业务处理之前：

| 位置 | 作用 |
|---|---|
| `MessageHook.onX9Message` | 不触发点歌、关键词回复、语音播报 |
| `MsgReceiveHook.onMessageInserted` | 不送 AI、不重复点歌、不处理图片 |
| `AutoForwardHook.onMsgInsert` | 不进入来源/类型判定，直接不转发 |

取不到自己的 wxid 时返回 false，退回原有水印/账本逻辑，不丢真实消息。

## 三、白名单复核

| 路径 | 结论 |
|---|---|
| `MessageHook` → `maybeHandle` | `inWhitelist` 在第 108 行硬判定，false 直接返回 |
| `MsgReceiveHook` → `maybeHandle` | 同上，非白名单指令被吞掉，不送 AI |
| `TriggerEngine.isSongRequest` | 自带白名单，非白名单指令按普通聊天走 |
| 空白名单 | `inWhitelist` 固定 false，任何会话都不触发 |

白名单判定在产物账本之前，非白名单会话不存在「先命中账本再放行」的缺口。

 对比 8.0.49 vs 8.0.76 的语音写入路径差异

一、问题1: stop() 能否返回 true?
================================================================================

  Smali 行 359-361:
    const/4 v0, 0x1      ; 成功 → 返回 true
    move v2, v0
    goto :goto_1ab

  Smali 行 442-443:
    const/4 v0, 0x0      ; 失败 → 返回 false
    move v2, v0

  结论: ✅ stop() 一定能返回 true!
        条件是: duration >= 800ms 且文件写入成功
        如果 duration < 800ms, 走 cond_165 分支, 返回 false

  用 "置null c 绕过" 的方法:
    → 如果把 this.p 设为非2, 会走到 cond_13d 分支 (不是 cond_12d)
    → cond_13d 是旧语音路径, 也会成功并返回 true
    → 但要确保 p 被正确修改


二、问题2: 8.0.76 DB写入路径 (双路径)
================================================================================

  stop() 中两个DB写入路径:

  ┌─────────────────────────────────────────────────────────────┐
  │ PATH A: 旧语音路径 (cond_13d, Smali 行325-338)              │
  │                                                             │
  │   y21.x0.t(this.e, this.m, 0, this.h)                      │
  │     参数1: this.e → String     语音文件路径                 │
  │     参数2: this.m → int        录音时长(ms)                 │
  │     参数3: 0 → int             标志位                       │
  │     参数4: this.h → e9         MsgInfo消息对象              │
  │                                                             │
  │   y21.x0.t() 内部:                                          │
  │     → j(str) 获取 y21.w0 (voicestg记录)                    │
  │     → new e9() 创建消息对象                                 │
  │     → y1(j.c) 设置talker                                   │
  │     → setType(34) 语音类型                                  │
  │     → k1(1) 设置某标志                                      │
  │     → j1(filePath) 设置文件路径                             │
  │     → d1(u0.c(j.n, j.l, false)) 设置语音XML content         │
  │     → e1(x9.o(j.c)) 设置时间                                │
  │     → o3(i2) 设置另一个标志                                  │
  │     → a.a.d(e9Var) 可能是版权/权限设置                       │
  │     → w(j) 写入DB                                           │
  │                                                             │
  │   然后: y21.p0.kj().e() — 刷新播放列表                      │
  ├─────────────────────────────────────────────────────────────┤
  │ PATH B: 新语音路径 (cond_12d, Smali 行300-322)              │
  │                                                             │
  │   bg0.d.k = p55.c.a.b(msgInfo) — msgInfo→protobuf          │
  │   ((cg0.f)n0.c(cg0.f.class)).zj(this.f) — 提交发送任务     │
  │                                                             │
  │   其中:                                                     │
  │     cg0.f 实际类型 = Lig0/o (VoiceMsgFeatureService)        │
  │     zj(sj3.b0) → 将发送任务加入队列                        │
  │     this.f = jg0.x (extends sj3.c extends sj3.b0)           │
  │     this.f内部有 bg0.d (send params)                        │
  └─────────────────────────────────────────────────────────────┘

  选择哪个路径?
    Smali 行: if (this.p != 2) → 走 PATH A
              if (this.p == 2) → 走 PATH B

    this.p = 2 表示 "onPart" 模式 (新语音/分段发送)


三、g() 创建发送任务的过程 (PATH B 的初始化)
================================================================================

  g(toUser, msgInfo):
  
  1. 生成文件名 (Smali 行156-164):
     y21.g1.x0(z1.r(), "amr_") → 文件名
     → 存到 this.e

  2. 创建发送参数 (Smali 行166-194):
     bg0.d dVar = new bg0.d(toUser, fileName)
     dVar.j = this            // 引用录音器
     dVar.i = 0               // 初始化状态
     
     jg0.x task = new jg0.x(dVar)  // 创建发送任务
     this.f = task              // 保存发送任务
     
     // jg0.x extends sj3.c extends sj3.b0 (BaseSendMsgTask)

  3. 注册到协程 (Smali 行222-257):
     if (task instanceof sj3.c) {
       task.g = r2.b(...)   // 设置 flow
       // 在 coroutine scope 中启动
       i.c(scope, ..., new j0(task), ...)
     }

五、tl.x0 的角色变化 (8.0.49 → 8.0.76)
================================================================================

  8.0.49: tl.x0 (完整发送任务)
    - t(String, int, int, e9) → 写DB
    - a() → 执行发送

  8.0.76: tl.x0 (简化)
    - 只剩 a() → void (14行, 仅做清理/错误处理)
    - a() 内容:
      → y0Var.a.a()            — 某回调
      → y0Var.d.a()            — 某回调(如果存在)
      → y0Var.b.d()            — 停止录音
      → y0Var.e = -1           — 重置状态

    不再直接操作 DB! DB写入已迁移到:
      PATH A: y21.x0.t()  (旧语音, stop()中直接调)
      PATH B: Lig0.o.zj() (新语音, 通过发送任务)


六、8.0.76 语音发送完整流程 (总结)
================================================================================

  [录制阶段] tl.p0.g(toUser, msgInfo)
       │
       ├─ y21.g1.x0() 生成文件名
       ├─ bg0.d 创建发送参数
       ├─ jg0.x 创建发送任务 → this.f
       └─ tl.o0.run() 开始硬件录音

  [停止阶段] tl.p0.stop()
       │
       ├─ duration < 800ms → 清理/丢弃 → return false
       │
       ├─ PATH A (旧语音, this.p != 2):
       │   y21.x0.t(fileName, duration, 0, msgInfo)
       │   → 创建 e9 → setType(34) → 写DB
       │   y21.p0.kj().e()
       │   → 刷新播放列表
       │
       ├─ PATH B (新语音, this.p == 2):
       │   bg0.d.k = p55.c.a.b(msgInfo)
       │   ((cg0.f)n0.c(cg0.f.class)).zj(this.f)
       │   → 提交发送任务 (后台协程)

  [发送阶段] jg0.x (extends sj3.c)
       │
       └─ coroutine flow 中执行
          → 读文件 → 上传 → onSceneEnd回调


七、如何在你的模块中调用DB写入
================================================================================

  [方式1] 调用 y21.x0.t() — 最直接 (PATH A)
  ──────────────────────────────────────────
  XposedHelpers.callStaticMethod(
      XposedHelpers.findClass("y21.x0", cl),
      "t",
      fileName,      // String: 语音文件完整路径
      durationMs,    // int:    录音时长(ms)
      0,             // int:    标志位(0)
      msgInfo        // e9:     MsgInfo消息对象
  );
  // 返回 boolean — true=写入成功

  [方式2] 通过 Lig0.o.zj() — 新路径 (PATH B)
  ──────────────────────────────────────────
  // 需要构造完整的 jg0.x + bg0.d

  // 1. 创建发送参数
  Class<?> bg0d = XposedHelpers.findClass("bg0.d", cl);
  Object params = XposedHelpers.newInstance(bg0d, talker, fileName);
  XposedHelpers.setIntField(params, "h", durationMs);

  // 2. 创建发送任务
  Class<?> jg0x = XposedHelpers.findClass("jg0.x", cl);
  Object task = XposedHelpers.newInstance(jg0x, params);

  // 3. 提交
  Class<?> cg0f = XposedHelpers.findClass("cg0.f", cl);
  Object service = XposedHelpers.callStaticMethod(
      XposedHelpers.findClass("pa5.n0", cl), "c", cg0f);
  // service 实际是 Lig0.o 实例
  XposedHelpers.callMethod(service, "zj", task);

  [方式3] 直接构造 e9 写入 f9.Ra() — 绕过语音API
  ──────────────────────────────────────────
  // 构造 MsgInfo(type=34)
  Object msg = XposedHelpers.newInstance(e9Class, talker);
  XposedHelpers.callMethod(msg, "setType", 34);     // 语音类型
  XposedHelpers.callMethod(msg, "setContent",       // 语音XML
      talker + ":" + durationMs + ":0");
  XposedHelpers.callMethod(msg, "setCreateTime", System.currentTimeMillis());
  // 设置文件路径
  XposedHelpers.callMethod(msg, "y1", fileName);    // 可能是 setImgPath
  
  // 写入DB
  Object f9 = getF9Instance();
  XposedHelpers.callMethod(f9, "Ra", msgId, msg);


八、回答你两个问题的最终答案
================================================================================

  Q1: stop() 现在能不能返回 true?
  ─────────────────────────────
  A: ✅ 能! 
     duration >= 800ms → Smali 行359 v0=1 → return true
     duration < 800ms  → Smali 行442 v0=0 → return false

     用 "置null c" 绕过的风险:
     → this.p 控制 PATH A/B 选择
     → 不是 c 字段, 而是 p 字段
     → Smali 中: if (this.p != 2) → PATH A; else → PATH B

  Q2: 8.0.76 DB写入方法?
  ─────────────────────
  PATH A (旧语音): y21.x0.t(String fileName, int duration, int flag, e9 msgInfo)
  PATH B (新语音): Lig0.o.zj(sj3.b0 task)  → 内部由发送任务处理DB写入

  tl.x0.a() 在8.0.76中不写DB! 只做清理。

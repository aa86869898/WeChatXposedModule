一、原理概述
================================================================================

  微信使用自研的 WCDB（腾讯开源数据库引擎）存储数据。
  WCDB 基于 SQLCipher，数据库文件是加密的，需要密码才能打开。

  ★ 核心思路 ★
  不自己引入 WCDB/SQLCipher 的第三方 jar 包。
  直接反射调用微信进程里已经加载好的 ka5.f.s() 方法。
  微信帮你处理了所有加密细节（SQLiteCipherSpec、kdf_iter、page_size 等）。

  只需要传给 ka5.f.s() 两个参数：文件路径 + 7位密码。


================================================================================
二、数据库文件路径
================================================================================

  路径组成:

    {数据目录}/MicroMsg/{uin哈希}/EnMicroMsg.db

  具体计算:

    数据目录 = mp0.b.X()
              → "/data/user/0/com.tencent.mm/"

    uin哈希  = hm0.b0.e((int) uin)
              → 实际是 MD5("mm" + uin)
              → 如 "7b998556beeef3a1552aa84157df99e8"

  完整路径示例:

    /data/user/0/com.tencent.mm/MicroMsg/
      7b998556beeef3a1552aa84157df99e8/EnMicroMsg.db


================================================================================
三、数据库密码计算
================================================================================

  密码组成:

    MD5( IMEI + uin ).substring(0, 7)

  唯二需要的参数:

    参数1: uin  (微信用户ID，数字)
    参数2: IMEI (设备IMEI，取不到时用兜底值)

  伪代码:

    imei  = wo.w0.g(true)        // 尝试获取设备IMEI
           // 如果取不到，返回兜底值: "1234567890ABCDEF"

    input = imei + uin           // 字符串拼接，如 "1234567890ABCDEF295734952"
    md5   = kk.k.g(input.getBytes("UTF-8"))  // MD5 哈希
    pwd   = md5.substring(0, 7)  // 取前 7 个字符 → 如 "e13b6eb"

  关键类方法:

    类名: wo.w0
    方法: g(boolean) → String
    说明: 获取设备 IMEI。参数 true 表示取不到时返回 "1234567890ABCDEF"

    类名: kk.k
    方法: g(byte[]) → String
    说明: 计算 MD5 哈希，返回 32 位十六进制小写字符串

  ★ 密码候选枚举策略（应对换卡/多设备）

    候选1: wo.w0.g(true)             → 设备当前 IMEI
    候选2: "1234567890ABCDEF"        → 微信硬编码兜底密码
    候选3: IMEISave.a() 历史记录    → 换卡前的旧 IMEI

    逐个尝试，直到 SELECT FROM rcontact 成功为止。

四、打开加密数据库（核心！）
================================================================================

  ★★★ 这是整个方案最关键的一行调用 ★★★

    类名: ka5.f
    方法: s(String path, String password, int flags, boolean useWAL) → ka5.f

    参数:
      path     — 数据库文件完整路径
      password — 7位密码字符串
      flags    — 传 0 即可
      useWAL   — 传 true（启用 WAL 日志模式）

    返回值:
      ka5.f 实例，内部包装了 com.tencent.wcdb.database.SQLiteDatabase

  伪代码:

    ka5f = Class.forName("ka5.f")
    s    = ka5f.getMethod("s", String.class, String.class, int.class, boolean.class)
    db   = s.invoke(null,
              dbPath,    // "/data/user/0/com.tencent.mm/MicroMsg/7b998.../EnMicroMsg.db"
              "e13b6eb", // 7位密码
              0,         // flags
              true)      // useWAL

  ★ 验证是否成功 ★

    // 查询 sqlite_master，确认 rcontact 表存在
    Method u = db.getClass().getMethod("u", String.class, String[].class)
    Cursor c = (Cursor) u.invoke(db,
        "SELECT name FROM sqlite_master WHERE type='table' AND name='rcontact'",
        null)
    if (c.moveToFirst()) → 密码正确，数据库打开成功！

  ★ 执行查询 ★

    Cursor c = (Cursor) u.invoke(db,
        "SELECT username, nickname, conRemark FROM rcontact WHERE type=4 LIMIT 10",
        null)
    while (c.moveToNext()) {
        String nickname = c.getString(c.getColumnIndex("nickname"))
        String username = c.getString(c.getColumnIndex("username"))
    }
    c.close()

  ★ 关闭数据库 ★

    Method close = db.getClass().getMethod("c")
    close.invoke(db)

  ★ 为什么不用 SQLiteDatabase.openOrCreateDatabase() 直接打开？ ★

    之前尝试过直接调用 WCDB 的 SQLiteDatabase.openOrCreateDatabase()，
    但因为没传 SQLiteCipherSpec 参数，导致静默创建了一个空白的新数据库，
    而不是打开已有的加密数据库。

    ka5.f.s() 内部做了:
      1. bytes = password.getBytes()
      2. SQLiteCipherSpec cipherSpec = ka5.f.l  (微信预设的加密参数)
      3. SQLiteDatabase.openDatabase(path, bytes, cipherSpec, ...)
      4. 设置 trace callback、checkpoint callback
      5. 返回包装后的 ka5.f 实例

    如果自己调用 openDatabase()，需要搞清楚 WCDB 的加密参数细节，
    这是不必要的工作量 —— 微信已经帮你封装好了。

六、联系人 type 值含义
================================================================================

  微信 8.0.76 实测分布（rcontact 共 13773 行）:

    type    数量      含义
    ─────────────────────────────
    4       13617     ★ 好友（联系人主体）
    3       99        群聊（@chatroom）
    2       27        群聊（@chatroom，旧格式）
    33      24        系统功能号（文件传输助手、QQ邮箱提醒等）
    2049    1         文件传输助手
    1       1         临时会话 / 陌生人
    259     1         未知
    2050    1         未知
    2051    1         未知

  ★ 查询好友的 SQL ★

    SELECT username, nickname, alias, conRemark, type
    FROM rcontact
    WHERE type = 4 AND deleteFlag = 0
    ORDER BY CASE WHEN length(conRemarkPYFull) > 0
             THEN upper(conRemarkPYFull)
             ELSE upper(quanPin) END ASC

  ★ 兼容旧版本 ★

    旧版微信的 type 编码可能不同，可以用 OR 组合:

    WHERE type = 4 OR type = 3 OR (type & 64 != 0)

    如果在新版本上失效，建议先做一次诊断查询:

    SELECT type, count(*) AS cnt
    FROM rcontact
    GROUP BY type ORDER BY cnt DESC

    看 type 分布，数量最多的通常就是好友。

七、完整调用链总结
================================================================================

  输入: 无（自动从微信进程获取 uin + IMEI）
  输出: Cursor，可遍历所有联系人

  步骤  类/方法                                  作用
  ───────────────────────────────────────────────────────────────
  ①     system_config_prefs 读 default_uin     获取 uin
  ②     wo.w0.g(true)                          获取 IMEI
  ③     kk.k.g(byte[])                         计算 MD5
  ④     MD5(IMEI + uin).substring(0, 7)        获取 7 位密码
  ⑤     mp0.b.X()                              获取数据目录
  ⑥     hm0.b0.e(int)                          MD5("mm" + uin)
  ⑦     拼接路径                                得到完整 db 路径
  ⑧     ka5.f.s(path, pwd, 0, true)            ★ 打开加密数据库
  ⑨     ka5.f.u(sql, null) → Cursor            执行 SQL
  ⑩     ka5.f.c()                              关闭数据库

八、Java 反射代码清单
================================================================================

  以下是最精简的完整代码，复制到 Xposed 模块中即可使用。
  只需要 Xposed API（compileOnly），零第三方依赖。

  ─── 代码开始 ───

  // 1. 获取 uin
  SharedPreferences sp = context.getSharedPreferences("system_config_prefs", 0);
  long uin = Long.parseLong(sp.getAll().get("default_uin").toString());

  // 2. 获取 IMEI
  Class<?> wo_w0 = cl.loadClass("wo.w0");
  Method gImei = wo_w0.getDeclaredMethod("g", boolean.class);
  String imei = (String) gImei.invoke(null, true);
  if (imei == null || imei.isEmpty()) imei = "1234567890ABCDEF";

  // 3. 计算密码
  Class<?> kk_k = cl.loadClass("kk.k");
  Method md5 = kk_k.getDeclaredMethod("g", byte[].class);
  String pwd = ((String) md5.invoke(null,
      (Object) (imei + uin).getBytes("UTF-8"))).substring(0, 7);

  // 4. 计算路径
  String base = (String) cl.loadClass("mp0.b").getMethod("X").invoke(null);
  String hash = (String) cl.loadClass("hm0.b0")
          .getMethod("e", int.class).invoke(null, (int) uin);
  String dbPath = base + "MicroMsg/" + hash + "/EnMicroMsg.db";

  // 5. ★ 打开数据库 ★
  Class<?> ka5f = cl.loadClass("ka5.f");
  Method s = ka5f.getDeclaredMethod("s",
          String.class, String.class, int.class, boolean.class);
  Object db = s.invoke(null, dbPath, pwd, 0, true);

  // 6. 查询联系人
  Method u = db.getClass().getDeclaredMethod("u", String.class, String[].class);
  Cursor c = (Cursor) u.invoke(db,
      "SELECT username, nickname, alias, conRemark, type " +
      "FROM rcontact WHERE type=4 AND deleteFlag=0 LIMIT 200",
      null);

  while (c.moveToNext()) {
      String username = c.getString(c.getColumnIndex("username"));
      String nickname = c.getString(c.getColumnIndex("nickname"));
      String conRemark = c.getString(c.getColumnIndex("conRemark"));
      String display = (conRemark != null && !conRemark.isEmpty())
              ? conRemark : nickname;
      Log.i("WxContact", display + " (" + username + ")");
  }
  c.close();

  // 7. 关闭
  db.getClass().getMethod("c").invoke(db);

  ─── 代码结束 ───

九、常见问题排查
================================================================================

  Q1: 类名找不到 (ClassNotFoundException)
  A1: 混淆类名随微信版本变化。需要用 DexKit 做字符串特征搜索自动定位:
      - ka5.f:  搜索使用了 "EnMicroMsg.db" 字符串的类
      - kk.k:   搜索使用了 "MD5" 且方法签名 (byte[])String 的类
      - wo.w0:  搜索使用了 "1234567890ABCDEF" 字符串的类
      - mp0.b:  搜索使用了 "/MicroMsg/" 字符串的类
      - hm0.b0:  搜索 "mm" + uin 拼接模式的方法

  Q2: 数据库打开成功但 SELECT 报 "no such table: rcontact"
  A2: 密码正确但打开了错误/空的库。检查:
      - 路径是否正确
      - 是否有多个账号的目录
      - account.mapping 文件可以帮你映射 uin→hash 的关系

  Q3: type=4 查到 0 行
  A3: type 编码可能随版本变化。先做诊断:
      SELECT type, count(*) FROM rcontact GROUP BY type
      看数量最多的 type 值。

  Q4: 怎样获取 Context?
  A4: Android 11+:
      Context ctx = ActivityThread.currentActivityThread().getSystemContext();
      或从 mp0.b 的静态字段 x2.a.a 获取。

  Q5: 数据库文件存在但文件大小为 0 MB?
  A5: 可能是 WCDB 的 WAL/SHM 文件占用了实际数据。
      确保 -wal 和 -shm 文件也存在，WCDB 会自动合并。
      如果大小为 0，可能是密码错误导致打开了空白库。

  Q6: 是否支持非 root 设备?
  A6: Xposed 模块运行在微信进程内，有文件读写权限，不需要 root。
      但如果做离线分析（PC端），需要 root 或 ADB backup 导出文件。
